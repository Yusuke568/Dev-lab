# SES勤怠管理・勤務報告書システム ドキュメント総合インデックス

## 1. ドキュメント体系と位置づけ

本リポジトリ（Dev-lab）は、Java 11 / Servlet 4.0 / MySQL 8.0 を基盤とした「SES勤怠管理・勤務報告書システム」のソースコードおよび設計ドキュメント群です。  
本ドキュメント群は、要件定義から基本設計、詳細設計、アーキテクチャ解説、オンボーディング手順までを網羅し、プロジェクト参画者が迷いなく開発・保守・拡張を行えるように体系化されています。

```text
00.document/
├── [要件定義フェーズ]
│   ├── 00_ドキュメント総合インデックス.md          # 本書：全体マップ・文書管理規約
│   ├── 01_システム概要・企画背景書.md              # 企画背景・SES業界課題・全体目標
│   ├── 02_機能要件定義書.md                        # 全業務機能の完全詳細仕様・入出力規則
│   └── 03_非機能要件定義書.md                      # 性能・可用性・セキュリティ・運用要件
├── [基本・詳細設計フェーズ]
│   ├── 04_アーキテクチャ設計書.md                  # ヘキサゴナル構造・レイヤー依存規則
│   ├── 05_データモデル設計書.md                    # ER図・全13テーブル定義・インデックス
│   ├── 06_画面・UI設計書.md                        # 画面遷移・各画面UI仕様・Tailwind設計
│   ├── 07_APIインターフェース仕様書.md             # 非同期JSON API・エンドポイント仕様
│   └── 08_ドメイン業務ロジック詳細設計書.md        # SES精算・36協定・有給計算アルゴリズム
└── [解説・オンボーディングフェーズ]
    ├── 09_アーキテクチャ設計思想とMVC転換ガイド.md # Ports & Adapters解説・Before/After
    ├── 10_SESドメイン業務知識解説書.md             # SES契約形態・労基法・メンタル管理
    └── 11_オンボーディング・開発環境構築手順書.md  # 3ステップ構築・初期アカウント・テスト実行
```

## 3. ロール別推奨リーディングパス

### パス A: 新規参加エンジニア（即戦力化パス）
1. `11_オンボーディング・開発環境構築手順書.md` を参照し、ローカル環境でアプリ起動と `mvn test` 成功を確認する。
2. `00_ドキュメント総合インデックス.md` で全体像を把握する。
3. `09_アーキテクチャ設計思想とMVC転換ガイド.md` で「なぜこの構成なのか」を理解する。
4. `04_アーキテクチャ設計書.md` および `10_SESドメイン業務知識解説書.md` で実装規約を把握する。

### パス B: 新機能・業務ロジック実装者
1. `02_機能要件定義書.md` で要求仕様とバリデーションルールを確認する。
2. `08_ドメイン業務ロジック詳細設計書.md` でドメインモデルの計算ルールを確認・設計する。
3. `05_データモデル設計書.md` でテーブル構造とリポジトリポートを特定する。
4. `07_APIインターフェース仕様書.md` および `06_画面・UI設計書.md` でUI連携を実装する。

### パス C: QA・テストエンジニア
1. `02_機能要件定義書.md` の入力・出力仕様および異常系フローからテストケースを策定する。
2. `08_ドメイン業務ロジック詳細設計書.md` の境界値条件（精算幅上下限、36協定閾値）を網羅するテストデータを設計する。
3. `03_非機能要件定義書.md` の性能・セキュリティ要件に基づき負荷・脆弱性検証を実施する。

## 4. ドキュメント更新・メンテナンス規約

1. **コード先行・ドキュメント同期の原則**: 仕様変更やテーブル追加を行った際は、必ず同一コミットまたは同一PR内で該当設計書を更新すること。
2. **粒度の維持**: コードの型定義・カラム名・エラーコードとドキュメントの記載が1対1で合致する精度を維持すること。
3. **Mermaidダイアグラムの活用**: 構造やシーケンスの可視化にはMermaidを用い、テキストコードとしてバージョン管理すること。
