## 2. 各機能の詳細仕様

### 2.1 認証・認可機能群

#### F-AUTH-01: ログイン・セッション認証
- **アクター**: 未認証の全ユーザー
- **事前条件**: なし（ログイン画面にアクセス可能であること）
- **事後条件**: 認証成功時、`UserSession` が `HttpSession` に格納され、トップ画面へリダイレクト。
- **入力項目**:
  - 社員ID (`username`): 数値、必須、1〜10桁
  - パスワード (`password`): 文字列、必須、1〜50文字
- **バリデーション規則**:
  - 未入力の場合: 「社員IDとパスワードを入力してください」を表示。
  - 数値以外の場合: 「社員IDは数値で入力してください」を表示。
- **処理フロー**:
  1. `LoginExecuteAction` がリクエストパラメータを取得。
  2. `JdbcAuthRepository`（または `login_table`）から該当社員IDのレコードを取得。
  3. `ENABLED` フラグが 1 であること、および有効期限内であることを検証。
  4. パスワード照合を実施。一致しない場合はログイン失敗画面へ遷移（エラーメッセージ設定）。
  5. 一致した場合、社員の役職コードから `UserRole`（`USER`, `MANAGER`, `ADMIN`）を判定。
  6. `UserSession` オブジェクトを生成し、`session.setAttribute("userSession", ...)` に保存。
  7. ロールに応じて適切な初期画面（USER: `sesAttendance.do`, MANAGER/ADMIN: `shainList.do`）へフォワード。

#### F-AUTH-02: ロールベースアクセス制御 (RBAC)
- **権限マッピング規則**:
  - `class_master.ID = '01'` (役員) / `'02'` (人事部長) → `UserRole.ADMIN`
  - `class_master.ID = '03'` (課長・PM) → `UserRole.MANAGER`
  - それ以外（一般社員等） → `UserRole.USER`
- **アクセス制御仕様**:
  - `USER`: 自身の勤怠・週報のみ編集可能。社員CRUDや有給管理画面へのアクセスは403 Forbiddenまたはエラー画面表示。
  - `MANAGER`: 担当社員の勤怠閲覧、週報レビューコメント付与が可能。
  - `ADMIN`: 全機能（社員CRUD、有給付与ルール設定・一括実行含む）の実行権限を保持。

#### F-AUTH-03: ログアウト
- **アクター**: 認証済みの全ユーザー
- **処理フロー**:
  1. `LogoutAction` が実行される。
  2. `session.invalidate()` を呼び出し、セッション情報を完全に破棄。
  3. `login.do` へリダイレクト。

### 2.2 社員管理機能群

#### F-SHAIN-01: 社員一覧表示・検索
- **アクター**: MANAGER, ADMIN
- **入力**: なし（将来的な検索クエリパラメータに対応可能な構造）
- **出力項目**:
  - 社員ID (`id`)、社員氏名 (`name`)、カナ (`namekana`)、入社年 (`entryYear`)、性別 (`gender`)、役職名 (`className`)、有給休暇残日数 (`paidLeaveDays`)
- **処理フロー**:
  1. `ShainListAction` が `ShainService.getAllShain()` を呼び出す。
  2. `ShainDao` が `staff_table` と `class_master` を外部結合（LEFT JOIN）して全件取得。
  3. `List<Shain>` をリクエストスコープに設定し、`shainlist.jsp` を描画。

#### F-SHAIN-02: 社員新規登録
- **アクター**: ADMIN
- **入力項目**:
  - 社員ID (`id`): 数値、4桁以上、必須、重複不可
  - 氏名 (`name`): 文字列、最大40文字、必須
  - フリガナ (`namekana`): 文字列、最大40文字、任意
  - 入社年 (`entryYear`): 数値、1900〜2100、必須
  - 性別 (`gender`): "男" または "女"、必須
  - 役職 (`classId`): `class_master` に存在するID、必須
  - 初期パスワード (`password`): 文字列、4文字以上、必須
  - 初期有給日数 (`paidLeaveDays`): 数値、0以上、デフォルト20
- **処理フロー**:
  1. 入力値の形式・必須チェック。
  2. `TransactionManager.execute(...)` を開始。
  3. `staff_table` へ社員レコードを `INSERT`。
  4. `login_table` へログイン用アカウント（`ENABLED=1`）を `INSERT`。
  5. 双方成功時にコミット。社員一覧へリダイレクト。

#### F-SHAIN-03: 社員情報更新
- **アクター**: ADMIN
- **入力項目**: 氏名、フリガナ、入社年、性別、役職コード、有給残日数
- **処理フロー**:
  1. `ShainUpdateFormAction` で既存データを取得してフォームに事前バインド。
  2. `ShainUpdateExecuteAction` で更新内容を検証。
  3. `ShainDao.update(con, shain)` を実行し、`staff_table` を更新。

#### F-SHAIN-04: 社員削除
- **アクター**: ADMIN
- **処理フロー**:
  1. `ShainDeleteFormAction` で削除確認画面を表示。
  2. `ShainDeleteExecuteAction` で `TransactionManager` を通じて `login_table` および `staff_table` の該当レコードを削除。

### 2.3 SES勤怠管理機能群

#### F-ATT-01: SES日次勤怠入力・保存 (Web / API)
- **アクター**: USER, MANAGER
- **入力項目 (JSON / Form)**:
  - 対象日 (`workDate`): `YYYY-MM-DD` 形式
  - 始業時刻 (`startTime`): `HH:mm` 形式（任意、未出勤時は空）
  - 終業時刻 (`endTime`): `HH:mm` 形式（始業時刻より後であること）
  - 休憩時間 (`breakMinutes`): 整数（分）、0以上
  - 中抜け時間 (`middleBreakMinutes`): 整数（分）、0以上
  - 適用区分 (`abstractId` / `leaveType`): 通常出勤、有給休暇、特別休暇、欠勤、法定休日、所定休日
  - 備考 (`remarks`): 文字列、最大200文字
- **ドメイン計算ルール (`DailyAttendance`)**:
  - `滞在時間 = 終業時刻 - 始業時刻`
  - `実労働時間 = 滞在時間 - 休憩時間 - 中抜け時間`
  - `法定時間外残業時間 = MAX(0, 実労働時間 - 8時間)`
  - 有給休暇取得日の場合: 実労働時間は0だが、有給付与フラグが立ち、実働日数・労働日数の集計に反映。
- **処理フロー**:
  1. フロントエンド (`ses_attendance.jsp`) より Fetch API で `/api/sesAttendance.do` に POST 送信。
  2. `SesAttendanceApiAction` が受信し、`FillAttendanceUseCase` を実行。
  3. ドメインモデル `DailyAttendance` が時間を計算・自己防衛バリデーション。
  4. `JdbcAttendanceRepository` 経由で `daily_attendances` テーブルへ UPSERT。
  5. 再計算された日次データおよび月間サマリー（総稼働、精算状況、36協定レベル）を JSON で返却。

#### F-ATT-02: 月間テンプレート一括適用
- **アクター**: USER, MANAGER
- **概要**: 対象年月の平日（月〜金）に対し、標準勤務時間（例: 09:00〜18:00、休憩60分、通常勤務）を一括で初期投入する。
- **処理フロー**:
  1. `ApplyMonthlyTemplateUseCase` を呼び出し。
  2. 対象月（1日〜末日）のカレンダーを走査。
  3. 土日祝日判定を実施。土曜日は「所定休日」、日曜日は「法定休日」に自動設定。
  4. 既に入力済みの確定行（`is_locked=true`）は上書きをスキップ。
  5. 未入力の平日に契約のデフォルト就業時間を一括登録。

#### F-ATT-03: 作業明細セグメント管理
- **概要**: 1日の実働時間を「直接作業時間（客先案件開発業務）」と「間接作業時間（自社全体会、社内研修、移動時間）」に分類して記録。
- **整合性ルール**: `直接作業時間 + 間接作業時間 = 当日の総実労働時間`。
- **永続化**: `work_time_segments` テーブルへ格納。

### 2.4 SES契約精算・労務コンプライアンス機能群

#### F-CON-01: SES契約精算計算
- **概要**: 案件契約（`project_contracts`）に設定された精算幅に基づき、当月の請求過不足を自動計算。
- **契約パラメータ**:
  - `billing_lower_limit_hours`: 精算下限時間（例: 140.0h）
  - `billing_upper_limit_hours`: 精算上限時間（例: 180.0h）
  - `standard_contract_amount`: 基準金額（例: 650,000円）
  - `overtime_unit_price`: 超過単価（円/h）
  - `deduction_unit_price`: 控除単価（円/h）
- **計算アルゴリズム (`SettlementService`)**:
  - `月間総実労働時間 < 精算下限時間` の場合:
    - ステータス: `DEDUCTION` (控除対象)
    - 不足時間 = `精算下限時間 - 総実労働時間`
    - 精算金額 = `基準金額 - (不足時間 × 控除単価)`
  - `精算下限時間 <= 総実労働時間 <= 精算上限時間` の場合:
    - ステータス: `WITHIN_RANGE` (精算幅内)
    - 精算金額 = `基準金額` (増減なし)
  - `総実労働時間 > 精算上限時間` の場合:
    - ステータス: `OVERTIME` (超過対象)
    - 超過時間 = `総実労働時間 - 精算上限時間`
    - 精算金額 = `基準金額 + (超過時間 × 超過単価)`

#### F-COMP-01: 36協定残業警告判定 (4段階)
- **概要**: 当月の法定時間外残業累計時間に基づき、リアルタイムで警告レベルを算出。
- **判定レベル定義 (`Article36ComplianceService`)**:
  | レベル | 時間条件 | UI表示・意味 |
  | :--- | :--- | :--- |
  | `NORMAL` | 残業時間 < 30.0h | 緑色バッジ: 良好な労務状態 |
  | `WARNING` | 30.0h <= 残業時間 < 45.0h | 黄色バッジ: 36協定通常限度(45h)への注意喚起 |
  | `DANGER` | 45.0h <= 残業時間 < 80.0h | オレンジバッジ: 特別条項発動域・過重労働注意 |
  | `VIOLATION`| 残業時間 >= 80.0h | 赤色点滅バッジ: 過労死ライン到達・違法リスク警告 |

#### F-COMP-02: 年5日有給取得義務監査
- **概要**: 労働基準法第39条第7項（年10日以上の有給が付与される労働者に対する年5日の時季指定義務）の遵守状況をチェック。
- **判定ルール (`PaidLeaveComplianceService`)**:
  - 基準日から当月までの消化日数をカウント。
  - 基準日から6ヶ月経過時点で取得日数が2日未満、または期末まで3ヶ月の時点で取得日数が3日未満の社員に対し「⚠️ 取得要請アラート」を画面表示。

### 2.5 有給休暇管理機能群

#### F-LEAVE-01〜03: 有給付与ルールおよび一括付与
- **付与基準マスタ (`leave_grant_rules`)**:
  - 0年（入社時）: 10日
  - 1年: 11日
  - 2年: 12日
  - 3年: 14日
  - 4年: 16日
  - 5年: 18日
  - 6年以上: 20日
- **一括付与バッチ処理仕様 (`LeaveService.grantAllStaffPaidLeave()`)**:
  1. システム当年の年度を取得。
  2. `staff_table` の全社員をループ。
  3. `勤続年数 = 現在年 - ENTRY_YEAR` を計算。
  4. 勤続年数に対応する `grant_days` を `leave_grant_rules` から検索（6年以上の場合は20日）。
  5. 社員の現在の `PAID_LEAVE_DAYS` に `grant_days` を加算。最大保有上限（前年繰越含む40日）で丸め処理。
  6. トランザクション内で全件一括更新。

### 2.6 週報・レビュー管理機能群

#### F-REP-01: 週報作成・提出
- **アクター**: USER
- **入力項目**:
  - 年週番号 (`yearWeek`): `YYYY-Www`（例: `2026-W41`）
  - 作業件名・工程名 (`taskTitle`): 文字列、必須、最大100文字
  - 作業進捗・詳細 (`taskProgress`): テキスト、必須、最大1000文字
  - 本人所感・課題 (`personalReflection`): テキスト、必須、最大1000文字
  - 来週の予定 (`nextWeekPlan`): テキスト、任意、最大500文字
  - 業務負荷スコア (`workloadScore`): 1〜5の5段階整数
  - 心身健康スコア (`healthScore`): 1〜5の5段階整数
  - エスカレーション要請 (`escalationNeeded`): チェックボックス（真偽値）
- **ステータス遷移**:
  - `DRAFT`（下書き保存）
  - `SUBMITTED`（提出完了・上司レビュー待ち）
  - `APPROVED`（承認完了）
  - `REJECTED`（差戻し・要修正）

#### F-REP-02: 負荷・健康アラート検知
- **自動エスカレーション条件**:
  - `healthScore <= 2`（健康状態に強い不安がある場合）
  - または `workloadScore >= 4`（業務負荷が過重である場合）
  - または `escalationNeeded == true`
- **検知時アクション**:
  - 管理職向けダッシュボードでハイライト表示し、優先フォロー対象として通知。

#### F-REP-03: レビューコメント付与
- **アクター**: MANAGER, ADMIN
- **機能仕様**:
  - 提出された週報に対してフィードバックコメントを記録。
  - `is_private_to_mgmt` フラグを有効にすることで、本人には非公開（営業・管理職間のみで共有するメモ）としてコメントを保存可能。
