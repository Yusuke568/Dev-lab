# SES勤怠管理・勤務報告書システム SESドメイン業務知識解説書

## 1. SES業界の契約形態と基礎知識

### 1.1 準委任契約とSES（システムエンジニアリングサービス）
IT業界におけるエンジニアの調達・契約形態には主に3種類が存在します。本システムは「SES（準委任契約）」に特化した業務ルールを実装しています。

| 契約種別 | 契約の目的 | 完成責任 | 指揮命令権 | 報酬の対価 |
| :--- | :--- | :---: | :--- | :--- |
| **請負契約** | 成果物（システム等）の完成・納品 | **あり** | 自社（受託企業） | 成果物そのもの |
| **SES（準委任契約）** | 善管注意義務に基づく専門的な労働力の提供 | **なし** | **自社（受託企業）** | **労働時間・提供能力** |
| **労働者派遣** | 労働力の提供 | なし | **派遣先企業（クライアント）** | 労働時間 |

> **重要コンプライアンス**: SES（準委任契約）では、クライアント企業が自社エンジニアに対して直接指揮命令を下すことは法律（労働者派遣法・偽装請負防止法）で固く禁じられています。業務指示や残業要請は、自社の営業・プロジェクト責任者を通じて行われる必要があります。

## 2. SES特有の契約精算幅（上下限時間）の商習慣

### 2.1 なぜ「精算幅」が存在するのか？
カレンダー上の営業日数は、2月（約18〜19営業日）から大型連休のない月（約22〜23営業日）まで月によって大きく変動します。  
もし完全固定時間（例: 月160時間ぴったり）で契約すると、毎月端数の精算が発生して双方の経理処理が破綻します。そのため、**「この時間幅（例: 140時間〜180時間）に実働時間が収まっている限りは固定の基準契約金額とする」** という商習慣（精算幅）が確立されました。

### 2.2 精算パターンの種類
1. **幅型契約（本システム対応）**:
   - 下限時間: 140.0時間
   - 上限時間: 180.0時間
   - 基準金額: 600,000円
2. **中間時間単価方式**:
   - 中間時間 = `(140 + 180) ÷ 2 = 160.0時間`
   - 超過・控除単価 = `600,000円 ÷ 160.0時間 = 3,750円/時間`
3. **上下割方式（本システム対応）**:
   - 超過単価 = `600,000円 ÷ 180.0時間 = 3,333円/時間`（上限で割るため安くなる）
   - 控除単価 = `600,000円 ÷ 140.0時間 = 4,285円/時間`（下限で割るため高くなる）

## 3. 労働基準法コンプライアンスの法的根拠

### 3.1 労働基準法第36条（36協定・時間外労働上限）
2019年の働き方改革関連法により、残業時間の上限が法律で罰則付きで義務化されました。

| 規定区分 | 法律上の上限時間 | システム内の判定レベル |
| :--- | :--- | :--- |
| **原則限度** | **月45時間**、年360時間 | `WARNING` (30h〜45h未達時点で警告) |
| **特別条項発動時** | **月100時間未満**（休日労働含む）<br>2〜6ヶ月平均 **80時間以内** | `DANGER` (45h〜80h未達時点で警告) |
| **過労死ライン** | **月80時間超** | `VIOLATION` (80h到達で即座に違法アラート) |

### 3.2 労働基準法第39条第7項（年5日有給休暇取得義務）
- **対象者**: 雇入れから6ヶ月経過し、出勤率8割以上で年10日以上の有給休暇が付与されたすべての労働者。
- **義務内容**: 使用者は、基準日から1年以内に**必ず5日の有給休暇を取得させなければならない**（違反時は労働者1人あたり最大30万円の罰金）。
- **システムの役割**: 基準日からの経過月数に応じて、「期末に消化が間に合わなくなるリスク」を判定し、早期に有給取得を促すアラートを発行。

### 3.3 休憩時間・休日の法的ルール
- **法定休憩時間（第34条）**:
  - 労働時間が6時間を超える場合: 少なくとも45分の休憩が必要。
  - 労働時間が8時間を超える場合: 少なくとも1時間の休憩が必要。
- **法定休日と所定休日の峻別（第35条）**:
  - **法定休日**: 法律で義務付けられた週1日（または4週4日）の休日（原則: 日曜日）。出勤した場合は割増賃金率 35% 以上。
  - **所定休日**: 会社規程や客先カレンダーで定めた休日（原則: 土曜日・祝日）。出勤した場合は週40時間超えの分について割増賃金率 25% 以上。

## 4. エンジニアのメンタルヘルス管理と週報の意義

客先常駐エンジニアは、「自社への帰属意識の希薄化」や「客先での過密労働・人間関係のトラブル」に直面しやすいリスクを抱えています。

### 4.1 週報で収集する指標と意味
- **業務負荷スコア (`workloadScore`: 1〜5)**:
  - 1: 余裕がある（タスク不足・待機の可能性）
  - 3: 適正（予定通り推移）
  - 5: 限界・過密労働（納期逼迫、炎上プロジェクトの予兆）
- **心身健康スコア (`healthScore`: 1〜5)**:
  - 1: 心身に強い不調（休職・離職リスク直結）
  - 3: 通常
  - 5: 非常に良好
- **エスカレーション要請フラグ (`escalationNeeded`)**:
  - エンジニア自身が「自社の営業や上司に相談したい」というSOSのサイン。フラグ検知時は即座に営業担当者へ通知し、客先ヒアリングや案件調整を実施。
