## 1. 変遷の4つのフェーズ（歴史のタイムライン）

本システムは、最初から現在のクリーンアーキテクチャで作られていたわけではありません。
現場の課題と要件の複雑化に対応する中で、4つの段階を経て進化してきました。

```
[Phase 1: 立ち上げ期]  ──▶ [Phase 2: 課題爆発期] ──▶ [Phase 3: 設計刷新期] ──▶ [Phase 4: 現場適応期(現在)]
・クラシックMVC          ・SES業務要件の複雑化     ・クリーンアーキテクチャ   ・中抜け休憩自動計算
・JSP + Servlet + DAO    ・デグレ多発・テスト不能   ・自己防衛ドメイン         ・休日表示 / クリア機能
・貧血JavaBeans          ・ロジックの散乱          ・単体テスト20件(0.8秒)    ・Tailwind静的化
```

---

### Phase 1: 立ち上げ期（クラシックMVC）
- **当時の構造**: JSP + FrontController + Action + DAO + JavaBean。
- **特徴**: 社員一覧表示やログイン、単純な打刻テーブルのCRUD。
- **当時の評価**: 初期要件がシンプルだったため、素早い画面構築には適していた。

---

### Phase 2: 課題爆発期（SES業務要件の複雑化と限界）
- **追加された要件**:
  - 客先契約の精算幅（下限140h〜上限180hの控除・割増計算）
  - 36協定の残業監視（月45h上限、35h注意アラート）
  - 客先直接労働と社内間接労働（研修・帰社日）の分離
  - 週報多層承認（3分割入力、課長所見、所属長最終承認、長期休暇スキップ）
- **直面した限界**:
  - **ロジックの散乱**: Action、DAO、JSPのスクリプトレットにあちこち業務計算が書かれ、仕様変更時にデグレが多発。
  - **テスト不能**: DBとTomcatが動いていないとテストできず、単体テストが書かれない文化に。
  - **貧血ドメイン**: Beanはただのgetter/setterの箱であり、不正なデータ（合計時間と内訳が合わないデータ等）がDBに保存されてしまう。

---

### Phase 3: 設計刷新期（クリーンアーキテクチャ移行）
- **移行の決定打**:
  - 社内勉強会（ヘキサゴナル/クリーンアーキテクチャ）を経て、根本的なリファクタリングを決断。
- **実施内容**:
  - `com.example` パッケージを完全撤廃し、直下4層（`domain/`, `usecase/`, `infrastructure/`, `controller/`）へ移行。
  - **ドメインの完全孤立化**: ドメイン層からServlet/JDBCのimportを全廃し、標準Javaのみで自己防衛ロジック（`validateSegmentsIntegrity()` 等）を実装。
  - **超高速テストの確立**: JUnit単体テスト20件を整備し、DB・Tomcat不要で0.8秒で全パスする環境を構築。

---

### Phase 4: 現場適応期（現在：実務例外の吸収）
- **直近の改善**:
  - **休日出勤の常時表示**: 土日をスキップせず常にカレンダーに表示（初期値: 休日 `--:--`）。
  - **誤入力のクリア機能**: 物理削除ではなく、安全に初期/未入力状態に戻すリセット機能の追加。
  - **中抜けスケジュール対応**: 「直接09:00〜18:00、間接19:00〜20:00」というすきま時間を自動で中抜け休憩（60分）として合算し、整合性エラーを防ぐ自動計算UIを実装。
  - **Tailwind CSS 静的化**: CDN警告を解消し、本番運用に耐える静的CSS（20KB）を採用。

## 2. コード対比：従来のMVC vs 現在のクリーン構造

### 以前のコード（Action/DAO直結・貧血Bean）
```java
public class KintaiUpdateAction implements Action {
    public View execute(HttpServletRequest req) {
        Kintai k = new Kintai();
        k.setStartTime(req.getParameter("start"));
        k.setEndTime(req.getParameter("end"));
        
        // 業務ルールがActionの中にむき出し
        int hours = calc(k.getStartTime(), k.getEndTime());
        if (hours > 8) {
            k.setOvertime(hours - 8);
        }
        
        KintaiDao dao = new KintaiDao();
        dao.update(k); // DBエラー以外は何でも通ってしまう
        return new View("/kintai.jsp");
    }
}
```

### 現在のコード（4層クリーンアーキテクチャ）
```java
public class SesAttendanceApiAction implements Action {
    public View execute(HttpServletRequest req) {
        // 1. ControllerはパラメータをUsecase Inputに詰めて委譲するだけ
        FillAttendanceUseCase useCase = new FillAttendanceUseCase(attendanceRepo);
        
        // 2. ドメインエンティティ内部で自己防衛（不変条件チェック）
        DailyAttendance att = useCase.execute(input);
        
        // 3. 結果を安全にJSON返却
        return sendJson(att);
    }
}
```

## 3. 新しく参画する方へ

現在のアーキテクチャは、教科書的な綺麗さを求めた結果ではなく、**「現場の複雑な業務ルールとデグレの恐怖と戦い、開発者が安心して拡張できるように進化してきた歴史の結晶」**です。

新しくコードを書く際も、この変遷を踏まえ、**「業務ルールは必ずdomainに書き、自己防衛させる」**ルールを守ってください。
